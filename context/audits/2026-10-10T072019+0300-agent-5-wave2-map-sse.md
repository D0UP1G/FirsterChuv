## Цель и исходное состояние

Карта зрителя читала снимок матча и опрашивала его раз в 4 секунды; публичной сетки и списка турниров на backend не было, поэтому `/watch` оставался заглушкой, а карта работала только по прямой ссылке на матч.

## Выполненные изменения

- `frontend/src/api/client.ts`: `api.publicTournaments()`, `api.publicBracket(id)`, `publicMatchEventsUrl(matchId, afterEventId)`.
- `frontend/src/spectator/transport.ts`: сетка читается с `GET /public/tournaments/{id}/bracket` (режим «один матч» из прошлого среза удалён); подписка использует `EventSource` на `GET /public/matches/{id}/events`: `onOpen` на каждом подключении, `score.changed` передаётся странице, `stream.resync_required` и нечитаемый кадр запускают повторное чтение снимка, ошибка считается сбоем только при закрытом потоке (штатное переподключение браузера после лимита 55 с не мигает индикатором). Опрос снимка остаётся запасным вариантом для браузеров без `EventSource`.
- `frontend/src/spectator/SpectatorMapPage.tsx`: сетка запрашивается только по идентификатору турнира.
- `frontend/src/spectator/PublicTournamentsPage.tsx` (новый) и `App.tsx`: страница `/watch` показывает реальный список публичных турниров со ссылками на карты, состояния загрузки, ошибки с повтором, пустого списка; стили в `spectator.css`.
- `frontend/src/spectator/validation.ts`: идентификаторы проверяются как канонические UUID, а не только RFC 4122 v1–v8: идентификатор задачи приходит из импортированного пакета (демо-задача использует нулевой UUID), и карта на реальных данных падала с «invalid identifier».
- Тесты: `transport.test.ts` (9), `PublicTournamentsPage.test.tsx` (3), `validation.test.ts` (2). Backend, контракты, миграции не менялись.

## Решения и отклонения

Режим «один матч по прямой ссылке» удалён: публичная сетка теперь есть на backend, а второй путь только усложнял логику. Опрос оставлен запасным. Ссылка с токеном для турниров «по ссылке» в интерфейсе не добавлялась: заголовок `X-Tournament-Share-Token` ещё не отправляется (нужен разбор фрагмента URL и отдельный срез).

## Блокеры и риски

- Анимации сдачи и обгона по SSE на живых событиях не проверены: журнал событий создаётся только при вердикте судьи.
- В события SSE попадает только `score.changed`; `match.started`, `bracket.advanced` и другие типы ждут типизированных payload (A4).
