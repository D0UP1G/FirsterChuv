## Цель и исходное состояние

ROADMAP v5 называет P4-08 независимым READY для A3. `docs/quality/m0-demo.md` разрешает уже доступные auth/invite/bracket API smoke на disposable data и требует выдавать отсутствующие integration gates как `NOT_RUN`, а не считать test doubles доказательством. P3-04.2 и normalized import выполняются в отдельных worktree; их файлы не изменялись.

## Выполненные изменения

- Добавлен `scripts/acceptance/run_api_smoke.py`: изолированное временное SQLite хранилище, миграции, temporary application admin через существующую management command, локальный WSGI HTTP server только на `127.0.0.1`, отдельные cookie sessions и синтетические identity.
- Runner проверяет 13 ограниченных API сценариев: CSRF, запрет регистрации с `role=admin` и неуспешный login такой identity, admin/participant/anonymous write permissions, создание турнира и ограниченного invite, минимальный анонимный preview с private headers, два participant login/session, повторное принятие invite, генерацию двухместной сетки, доступ участника и отказ постороннему.
- Секреты и bearer invite token остаются в памяти; server access logs отключены, redirects/proxy отключены, evidence не включает email/пароли/cookies/HTTP bodies/raw URLs. Evidence не перезаписывает существующий файл.
- Опция `--sandbox` при доступном Engine запускает существующий bounded synthetic `sandbox/smoke.py`; она не меняет и не подменяет Judge/runtime verdict. Контракт и инструкции описаны в `docs/quality/evidence/README.md`.
- В собственной карточке записаны ID/ветка/base/пути, объём, результаты и границы.

## Решения и отклонения

Запущен loopback WSGI API только внутри этого процесса и на одноразовой SQLite; `.env`, общий database volume, внешние endpoints и production users не используются. Для полной очереди/worker recovery не запускались unit test doubles: production chain требует P3-04.2/frozen providers. Результаты HTTP smoke не конвертируются в PASS строк полного кейса.

## Блокеры и риски

Docker Engine отсутствует. На доступной базе нет полной M0 цепочки normalized importer → configured run → actual worker/judge → durable result/failure → score/winner/clock. Полный P4-08 остаётся `IN_PROGRESS`; acceptance зависит от интеграции owning PRs и exact integration SHA.
