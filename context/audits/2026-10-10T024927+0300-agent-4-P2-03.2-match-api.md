## Изменения

- Добавлены `GET /api/v1/matches/{id}`, `PATCH /api/v1/matches/{id}` и `POST /api/v1/matches/{id}/start`.
- GET разрешён admin и текущим активным участникам матча; чужой матч для participant скрыт через 404. Ответ формируется allowlist projection по v1 форме; SELECT для submission projection исключает source/compile diagnostics и ответ не выдаёт checksum/private bundle. Private response/error на `/api/v1` получает `Cache-Control: no-store`.
- PATCH принимает только `{problemIds, matchDurationSec, startMode}`; дубли и неизвестные поля отклоняются, UUID и точный integer проверяются строго. Обязательны session CSRF и непустой `Idempotency-Key`; runtime использует `DjangoProblemCatalog`, сохраняет версии задач/scoring defaults в immutable run snapshot. READY каталог и verified compiler остаются решающим producer contract.
- POST start принимает только `{}`, требует session CSRF и ключ, допускает только настроенный `manual` run в READY. Естественный retry на текущем RUNNING run не меняет начальный server `started_at`. `both_ready` не запускается через admin start до появления ready endpoint.
- Документация и тесты показывают промежуточное получение leader/task stats из завершённых submission verdict rows. Это не durable result ledger; finalization/winner/promotion и delayed accepted handling остаются P2-04.
