## Цель и исходное состояние

Подключить React-интерфейс организатора к уже интегрированным CRUD/directory/roster/invite API. Проверить admin flow и двух новых участников на одноразовой SQLite, не подменяя транспорт fixture/mock. Перед завершением выполнены `git fetch origin --prune`, сверка карточки Agent 4, ROADMAP v3, требований M01–M03, контрактов invite/API, текущей ветки и последней интеграции P4-01. `HEAD` и `origin/develop` остались на `f7f4e2d`; свежие PR #7, #15, #16 и #21 ещё не вошли в develop, изменений, требующих merge из develop, не было.

## Выполненные изменения

- Typed API client: tournament list/detail/create/update/delete, participant directory, roster assign/seed/remove и invite list/create/revoke/preview/accept; mutations отправляют CSRF, URL path segments кодируются.
- Admin UI: список и форма турниров, редактирование lifecycle-aware полей, каталог с именами без email, roster/cap/freeze/seed состояния, создание/копирование/отзыв приглашений, загрузочные/ошибочные/пустые состояния и inline confirmations.
- Public invite route: минимальный preview, явная ошибка для admin-аккаунта, сохранение безопасного `next` через регистрацию/вход, accept для participant и отображение серверных ошибок. Raw URL остаётся в состоянии вкладки; список API содержит только metadata. Добавлен `no-referrer`.
- Добавлены API/UI тесты и инструкции запуска/проверки в `frontend/README.md`.
- Обновлены `context/agents/agent-4.md` и отдельные записи P4-01 merge checkpoint/P4-02 audit. Общие `context/STATE.md`, чужие карточки, приложения и backend в этом feature-срезе не изменялись.

## Сверка с кейсом

Реализован UI срез для M01–M03 и T03–T05. В браузере подтверждены создание/настройка турнира, cap 2/2, seed 1/2, name-only directory, role refusal, регистрация/вход/accept двух новых participant identities, повторный idempotent accept, revoke и expired-link error. Истёкшая ссылка после срока показала `Приглашение недоступно` / `Срок действия приглашения истёк.`

Это не полный приёмочный результат T03–T05: две participant identities проходили сценарий последовательно в одном браузерном профиле с выходом между ними; независимые параллельные сессии и browser-проверка ручного admin assign/remove отдельно не выполнены. M03 automatic rating seed и полный case acceptance остаются вне подтверждённого результата. В `context/STATE.md` статус требований не менялся.

## Решения и отклонения

Интерфейс подключён к настоящему `/api/v1`; mock оставлен только в изолированных frontend tests. Directory просит только `id`/`displayName`; приватные email/code/source не выводятся. Admin-role refusal оставлен видимым в UI и подтверждён серверной ролью. Срок и max uses отправляются согласно API контракту; expiry/revoke ошибки остаются на public странице без приватных данных.
