## Выполненные изменения

- Добавлен `SubmissionWorker`: один цикл сначала пытается доставить due durable outbox, затем получает FIFO claim; корректный `JudgeResult` завершает claim, `JudgeInfrastructureError`/некорректный typed result уходят в retry без WA/RE и без выдуманного verdict.
- Пока executor работает, отдельный heartbeat продлевает lease без долгой SQLite-транзакции. Финальное сохранение и delivery по-прежнему требуют действующего токена/lease; устаревший worker не может записать результат.
- Добавлена `SUBMISSION_WORKER_FACTORY`. Без неё команда не создаёт тестовые или permissive adapters и завершает запуск с понятной `CommandError`; требуются queue service, executor и реальный `ResultSink`.
- Добавлена management command `run_judge_worker`, совместимая с уже существующей Compose командой: `--once`, `--max-jobs`, `--idle-sleep`, `--lease-seconds`. Неожиданные ошибки worker завершают процесс безопасным общим сообщением, не печатая exception diagnostics/source.
- Добавлены тесты FIFO/result priority, result delivery и recovery просроченного outbox, retry infra failure без verdict, invalid provider result, устаревший claim, restart recovery, heartbeat долгого исполнения, fail-closed factory и redaction ошибки команды.
- Обновлён `backend/apps/submissions/README.md` с operational и runtime границами.

## Решения и отклонения

- Использован app-local `SubmissionExecutor` port, который получает lease claim; изменение общего v1-контракта не требовалось. Реализация обязана резолвить immutable run snapshot по P3-04.4 до создания `TrustedJudgeJob`.
- Исправлять `compose.yaml` не пришлось: команда `run_judge_worker` уже объявлена P1-04. Общий Compose/runtime wiring намеренно не менялся.
- Recovery здесь относится к durable DB leases очереди и outbox. В модели нет sandbox process registry/ID, поэтому очистка orphan container/process не реализована и не приписывается этому срезу; она принадлежит P3-03 sandbox lifecycle.
- Полноценная инфраструктурная причина для A2 failure sink и runtime result/workspace adapters остаются P3-04.3–4. `INFRA_FAILED` здесь не превращается в результат участника.

## Блокеры и риски

- PR #15 не смержен, поэтому публикация PR P3-04.2 с GitFlow base `develop` пока дала бы дублирующий/грязный diff. Локальная feature-ветка содержит очередь через собственный merge commit; исходный PR/branch не менялся.
- Production `SUBMISSION_WORKER_FACTORY`, LocalJudge executor, immutable version/checksum resolver, CompetitionGateway/ResultSink adapters и failure sink пока не подключены. Команда без полного real runtime wiring отказывает.
- При ошибке обновления heartbeat worker не принимает verdict без действующего lease; работа восстанавливается очередью после expiry. Неожиданный provider exception останавливает command, сохраняя claim до recovery.
