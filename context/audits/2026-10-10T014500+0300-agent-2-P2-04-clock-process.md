## Цель и исходное состояние

Подключить persisted deadline reconciliation к лёгкому отдельному Django management process по `docs/architecture/match-engine.md`; не зависеть от judge worker, который может быть занят длительной проверкой. Сверены competition management commands, новые методы P2-04 persistence, ROADMAP и текущий PR. До изменения функция deadline работала только по прямому вызову; management command для competition отсутствовал.

## Выполненные изменения

- Добавлены `backend/apps/competition/management/commands/run_match_clock.py` и package `__init__.py`.
- Команда обходит только актуальные `RUNNING` runs с `started_at`; срез UUID-ов читается до транзакционных reconciliations, stale runs после race обрабатываются идемпотентным no-op.
- По умолчанию polling интервал 250ms; ограничен 50–60000ms. `--once` выполняет один sweep для операционного вызова и теста. Транзакции каждой пары/матча остаются короткими.
- `backend/apps/competition/ledger_persistence.py`: stale current-run change во время выборки стал no-op, а не конфликтом polling loop.
- `backend/apps/competition/tests/test_match_clock_command.py`: просроченный run завершает one-shot sweep и не дублирует событие; недедлайнный остаётся RUNNING; interval bounds проверяется.
- Карточка Agent 2 дополнена результатом и оставшимся deployment CONNECT.

## Сверка с кейсом

Поддерживает M05/T09 deadline → FINALIZING → pending receipt drain, через уже реализованный transaction boundary. Команда умеет запускаться как отдельный процесс, но общий compose/process supervisor в этот PR не добавлен — это shared deployment ownership координатора.

## Решения и отклонения

`--once` предназначен для ручной проверки/операционного вызова, continuous режим — для отдельного легковесного process manager unit. Production расписание, рестарт policy, Compose/ports остаются вне competition-owned app и потребуют короткого integration CONNECT; command не запускает judge и не меняет admission policy.

## Блокеры и риски

PR #58 всё ещё не интегрирован. Сами database semantics и polling command проверены локально, но deployment process manager не запускает эту команду автоматически. Общий runtime result/failure adapter всё ещё ожидает stable infrastructure failure DTO/Sink от A1.
