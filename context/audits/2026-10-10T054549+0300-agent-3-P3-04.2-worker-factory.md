## Изменения

- Добавлен `backend/apps/submissions/runtime.py`: production worker factory, executor, который разрешает version/checksum только по принятому `run_id + problem_id`, формирует `TrustedJudgeJob` и передаёт его в настоящий `LocalJudge`/`DjangoProblemCatalog`. `CompetitionSnapshotUnavailable` и ошибки БД преобразуются в typed infrastructure failure. Тестовые providers не подключаются.
- `backend/config/settings.py` указывает `SUBMISSION_WORKER_FACTORY` на production factory. Queue worker использует только result/failure части сервиса; admission остаётся за API и отдельным production wiring.
- Добавлен failure sink adapter к common v1. Результаты и infrastructure failure receipts идут через реальный `DjangoCompetitionGateway`; исходник и diagnostics в эти receipts не попадают.
- `DockerRunner` маркирует claim-owned containers owner, submission ID и lease token. Lease-aware recovery перечисляет только свой owner label, сверяет точные DB status/token/expiry и удаляет только истёкшие claims. Некорректные labels и ошибки Docker завершают recovery fail-closed. Worker повторяет recovery с периодом 10 секунд, чтобы позже удалить контейнер, чей lease ещё действовал во время предыдущей проверки.
- Добавлены тесты на snapshot pinning/mismatch, typed provider failure, adapter mapping, claim labels, сохранение живого lease, удаление истёкшего claim и fail-closed некорректных labels. Обновлены собственные submissions/judge README и карточка Agent 3.
