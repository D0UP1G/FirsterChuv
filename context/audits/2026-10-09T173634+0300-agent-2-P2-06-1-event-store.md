## Сверка с кейсом

- V01/V02 покрыты только durable записью и чтением одного authoritative `score.changed` event типа; tournament bracket snapshot/projector и live map не готовы.
- V03 не покрыто: ASGI SSE, heartbeat, `Last-Event-ID`, resync/backpressure и duplicate-frame/browser behavior отсутствуют.
- S02 лишь ограничено конструкцией этого slice: публичный HTTP endpoint не добавлялся, поэтому здесь нет анонимного read-access path; object/PublicAccess permissions не тестировались.
- Частичные unit-проверки относятся к T17 replay cursor и T20 event allowlist/private-field rejection. Полные T16/T17/T20 не пройдены.
- Только `score.changed` имеет достаточно конкретную v1 payload форму в fixture. Другие имена из `realtime.md` перечислены как будущие типы, но запись пока отвергается до собственных typed schemas; это не выдаётся за полный EventWriter implementation.

## Решения и отклонения

В feature добавлен store core, не endpoint: пока PublicAccessV1 отсутствует, production-доступ не мог бы быть разрешён безопасно. Чтение сервиса требует, чтобы будущий HTTP/SSE caller сначала выполнил PublicAccess check; тестовые вызовы не создают runtime bypass.

Event model использует UUID scope values без FK к competition модели, которой ещё нет в `develop`; это сохраняет независимость app и не импортирует незлитые модели. ID глобален и cursor упорядочен по ID. При state change producer должен вызывать writer внутри общей transaction; writer nested atomic участвует во внешней транзакции, rollback покрыт тестом.

Store пока принимает только fixture-backed `score.changed`; строгий schema selection выбрана вместо свободного JSON или guesses по неполным описаниям остальных event payloads. Это ограничение расширяется отдельным срезом, когда per-event schema согласована с producers/consumer-ом. Разделение P2-06 на store, snapshot/access и transport не меняет published API/event fixture.

## Блокеры и риски

- Score/run event producers не подключены; event rows пока не генерируются из live competition transitions.
- Другие документированные events (`match.started`, submission, finish/tie, bracket, restart/replacement) ждут конкретных typed payload shapes.
- PublicAccessV1, current Match/Run snapshot state и coherent `lastEventId` snapshot endpoint не реализованы. Не открывать endpoint до интеграции auth/access и safe projector.
- SSE reconnect/resync/slow-client bounds и браузерные duplicate-frame semantics остаются будущими проверками.
- Ветка PR #13 независима и сейчас отдельна; merging P2-04/P2-01 позже может потребовать обычной синхронизации feature и ручного сохранения обоих состояний agent card.
