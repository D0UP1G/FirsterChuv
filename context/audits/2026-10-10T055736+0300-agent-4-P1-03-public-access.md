## Цель и исходное состояние

ROADMAP v6 P1-03 требует anonymous public/unlisted view с отдельным share token (hash/expiry/revoke), read-only scope, защиту от IDOR/CSRF/cache/referrer/proxy spoofing, rate limits и безопасные логи. В develop существовали public-only `PublicAccessV1` и allowlisted public match snapshot; unlisted fail-closed. Share token provider и admin management routes отсутствовали.

Сверка с `docs/requirements.md`: S01/S02, TEAM01/TEAM02/TEAM06, T02/T20; кейс, страницы 5–7: зритель может быть без аккаунта и видит состояние борьбы, не получая private source; администраторские права глобальны, обычная регистрация остаётся participant. В React frontend и A3 deployment/config этот срез не вносил изменений.

## Выполненные изменения

- Добавлена `TournamentShareLink` и migration; срок обязателен, token URL-safe 256-bit, в БД сохраняется только SHA-256. Admin выдаёт секрет один раз; list response не раскрывает token/hash; revoke идемпотентен и действует сразу.
- Admin API: `GET/POST /api/v1/tournaments/{id}/share-links`, `DELETE /api/v1/tournaments/{id}/share-links/{shareLinkId}`; global active admin + CSRF, strict `expiresAt`, no-store/no-referrer.
- Public match API расширен для unlisted visibility с grant, строго в пределах его tournament. Неизвестная, другая, expired или revoked ссылка скрывается одинаковым 404. `GET /api/v1/public/matches/{id}` остаётся read-only, `public-match` allowlist; response и error envelope содержат no-store/no-referrer.
- Секрет не размещается в query/path: create response формирует `/watch/{tournamentId}#shareToken=...`; client должен прочитать fragment и передавать `X-Tournament-Share-Token`. Query token не авторизует. Это устраняет URI exposure для новых share tokens.
- Добавлен `RemoteAddressScopedRateThrottle`: login/register/invite-preview/public-snapshot больше не принимают IP из client-controlled `X-Forwarded-For`; public snapshot ограничен 120/minute, остальные scopes используют текущие rates. Общий API middleware сохраняет `no-referrer` после нормализации 404, а все `/api/v1` responses остаются `no-store`.
- Обновлены API/realtime/security/parallel contracts, ROADMAP v6, requirements/current STATE и Agent 4 card; опубликован ранний потребительский API contract для A5. Добавлен A3-owned proxy/dev logging follow-up request.

## Решения и ограничения

- Token передаётся через fragment→header, чтобы не логировать secret в HTTP URI и не передавать его в Referer; A5 consumer пока не изменён. Contract опубликован в API/parallel docs.
- Anonymous throttle использует непосредственный socket peer и игнорирует все forwarded headers. Это защищает от подмены XFF при прямом доступе к API, но клиенты за одним reverse proxy могут делить общий bucket. Текущий Compose использует один API process; multi-process потребует shared cache и согласованного trusted-proxy setup.
- A4 не редактировал A3-owned `deploy/nginx/default.conf`, `backend/config/settings.py` или Compose. Legacy invite endpoint продолжает содержать raw token в path; в проекте остаётся отдельный request A3 обеспечить redaction в Nginx access logs и Django development server. Этот runtime log sink не проверялся в Docker smoke; полную T20 log-redaction acceptance не заявляю.
- Новые share tokens не находятся в URI и обычная Nginx URI logging не может раскрыть их; custom tracing/APM headers не проверялись.
