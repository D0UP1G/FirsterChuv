# P2-02.1 — lifecycle guard для изменений сетки

## Цель и основание

Закрыть lifecycle-дефект PR #7: создание, reset и ручная замена пар не должны менять сетку турнира после перехода из `DRAFT`/`SCHEDULED`. Работа продолжает `feature/bracket-runtime`; перед изменениями в неё обычным merge включён свежий `origin/develop` `c5682dd657969b699e22b8a2815b5247ad5a1553` (merge commit `cecad71`). PR #7 перед обновлением имел HEAD `1952244`.

Задача P2-02.1 связана с M03/M04 и backend-сценариями T05/T06. Исходный кейс требует генерации и ручного редактирования сетки, обработки нечётного числа участников и сохранения последовательности турнира; матрица требований указывает источник на стр. 5 PDF.

## Выполненные изменения

- В `backend/apps/competition/services.py` добавлен `BracketLifecycleConflict` (HTTP 409, `tournament_not_editable`) и общий `_claim_editable_tournament`.
- Guard выполняет условный `UPDATE` строки турнира по статусам `DRAFT`/`SCHEDULED` первым data statement внутри транзакции. Это берёт SQLite write lock до чтения существующей сетки, проверки Matches или freeze roster и сериализует проверку с архивированием/стартом.
- `generate_bracket`, `reset_bracket` и `set_first_round_pairings` используют общий guard. Поэтому повторный generate также возвращает 409 после закрытия lifecycle, вместо возврата старой сетки.
- Проверены сохранность roster/freeze/matches/slots при отказе и успешная генерация для `SCHEDULED`. HTTP generate возвращает 409 в общем API error envelope.
- В merge актуального develop сохранены competition/problems app registrations, CI, контракты, аудиты и изменения других агентов; общий `context/STATE.md` вручную не менялся.

## Контракты и границы

Новые маршруты и миграции не добавлялись. Guard применён к уже существующим service mutations и endpoint generate. HTTP reset/full-pairings, DTO, `Idempotency-Key`, actor/reason audit и race/idempotency API tests относятся к P2-02.2 и не входят в этот срез. Полная приёмка T05/T06 остаётся открытой.
