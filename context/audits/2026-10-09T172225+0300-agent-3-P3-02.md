## Фактические изменения

- Добавлена app `backend.apps.problems` и её начальная миграция. В `settings.py` зарегистрирован только `ProblemsConfig`; API routes, модели аккаунтов/турниров и общие контракты не менялись.
- `archive.read_archive` читает ZIP в ограниченную map байтов, не вызывает `extract`/`extractall` и не пишет пути архива на host. Ограничения: архив 16 MiB, 4096 entries, 8 MiB/file, 64 MiB total unpacked, ratio 100:1, path 1024 bytes/depth 32; разрешены Stored/Deflate. Traversal/absolute/drive/backslash/дубликаты, encrypted entries, symlink/special Unix types, неподдерживаемая compression и size bombs отклоняются.
- `bundle.parse_problem_bundle` валидирует только внутренний normalized ProblemBundleV1: schemaVersion, UUID/version, public statement/assets/examples/limits/languages отдельно от private tests/checker/validator/reference. JSON duplicate keys, неизвестные compiler IDs, ошибочные лимиты, несуществующие/перепутанные private/public paths и MIME/signature mismatch отклоняются. Никакие package scripts не запускаются.
- Добавлены серверный `CompilerSpec` registry, immutable version/checksum records и разные DB-модели для public metadata/assets и private тестов/artifacts. `(problemId, version)` уникальна; одинаковый checksum идемпотентен, изменённое содержимое той же версии — conflict. `NOT_READY` может перейти в `READY` только после подтверждения compiler registry; переход к READY активирует первую готовую версию. `describe_ready` публикует только public DTO без checksum/tests/private artifacts; `load_bundle` ограничен доверенным Python-портом и fail-closed при отсутствующей readiness/registry verification.
- В production `cpp20` пока `verified=False`, поэтому новые versions не объявляются READY до доступного runtime proof. Тесты могут подставить verified registry только для проверки переходов состояния; verdict/execution fixtures не подменяются.
- Добавлены русскоязычный README внутренней схемы и synthetic unit fixtures. Они не объявлены пакетом организаторов.
