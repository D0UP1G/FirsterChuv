## Цель и границы

Подготовить минимальный повторяемый C++20 Docker smoke harness для A3-01 по `AGENTS.md`, `docs/architecture/judging.md`, `docs/requirements.md`, `ROADMAP.md`, `docs/operations/mvp-acceptance.md` и исходному кейсу. Кейс требует реальный вердикт, отдельную изоляцию выполнения, лимиты ресурсов и отсутствие сети/доступа к host и секретам (в частности J01, J03, S01, D06 и будущая T18). Формат официального пакета не предполагался: его README в checkout отсутствует.

## Выполненные изменения

- Добавлен закреплённый по manifest digest образ GCC 14.2.0 и container entrypoint с фиксированными режимами `compile` и `run`.
- Compile выполняется в отдельном непривилегированном контейнере. Бинарный артефакт с ограничением 8 MiB передаётся trusted host runner-у по Docker stdout; runner не исполняет его на хосте.
- Каждый run получает новый контейнер, один артефакт и один ввод. Ожидаемый ответ и fixtures остаются снаружи; пользовательский исходник не попадает в argv или Docker options.
- Настроены `network=none`, private PID namespace, read-only root, ограниченный tmpfs, UID/GID 65534, удаление capabilities, `no-new-privileges`, 512 MiB memory без swap, один CPU, 64 PID, лимиты размера входа/исходника/вывода и wall timeout.
- Добавлены smoke fixtures для ожидаемых OK/WA, timeout и output-limit; результат OK/WA вычисляется сравнением настоящего stdout с эталоном на host runner-е.
- Обновлены `sandbox/README.md` и собственная карточка `context/agents/agent-3.md`. `context/STATE.md` не изменялся, чужие feature-ветки/файлы не менялись.

## Сверка с кейсом и документацией

Разделение compile container и нового run container для каждой попытки соответствует границе из `docs/architecture/judging.md`; эталонный ответ остаётся на стороне runner-а. Harness не выдаёт ожидаемые результаты без результата настоящего контейнера и возвращает `NOT_VERIFIED` при недоступном Docker. Это лишь подготовленная реализация: требования к реальному sandbox и официальному пакету пока не закрыты, поэтому `A3-01` остаётся `IN_PROGRESS`.

## Блокеры и ограничения

- `A3-01d`: Docker Engine недоступен; реальные compile/run, OK/WA и hostile resource/network/host/secret проверки имеют статус `NOT_RUN`.
- `A3-01b`/`A3-01e`: официальный README/пакет отсутствует; нельзя подтвердить фактический формат, checker или задачу организаторов.
- Smoke fixtures проверяют только механизм, не интеграцию с официальным пакетом и не доказывают безопасность контейнера.
- Изменения находятся только в `feature/sandbox-proof`; `develop` не обновлялся, PR не создан.
