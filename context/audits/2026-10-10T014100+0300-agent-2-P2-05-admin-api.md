## Цель и исходное состояние

Добавить доверенный HTTP adapter для persisted P2-05 admin actions, используя существующую session auth и permission систему. Сверены `AGENTS.md`, `ROADMAP.md`, `docs/architecture/api.md`, текущие views/urls, `IsApplicationAdmin`, CSRF conventions и актуальный P2-05 сервис. До изменения сервисные переходы были persisted и имели durable command receipts, но API routes отсутствовали.

## Выполненные изменения

- `backend/apps/competition/views.py`: добавлены strict request serializers и admin views для `POST /matches/{id}/pause`, `resume`, `extend`, `technical-result`, `rematches`, `replacements`. Требуются existing `IsApplicationAdmin`, session CSRF и `Idempotency-Key`. Неизвестные поля отклоняются; actor ID берётся только из authenticated request; persisted service повторно проверяет admin из БД. Ответы запрещают cache.

- `backend/apps/competition/tests/test_admin_api.py`: проверены пауза/возобновление/продление, replay и reused-key conflict, rematch, technical result, replacement, participant rejection, missing CSRF, отсутствие key и лишнее actor поле.

## Решения и отклонения

API contract из `docs/architecture/api.md` использован как есть. Общий access boundary не менялся. Входной camelCase нормализуется существующим `CamelCaseJSONParser`, а serializers строго проверяют внутренние snake_case fields после parsing. Два неудачных targeted прогона выявили это преобразование; serializer names приведены к действующему parser contract до зелёного полного прогона.

## Блокеры и риски
