## Изменения

- Удалён `--pid=private`, который отвергает используемый Docker CLI. Собственные mount/network/host PID параметры не добавлялись. Docker указывает, что PID namespace изолирован по умолчанию; фактическую конфигурацию созданного контейнера всё ещё нужно проверить через Engine inspect ([Docker CLI reference](https://docs.docker.com/reference/cli/docker/container/run)).
- Supervisor до чтения запроса и создания дочернего процесса вызывает `prctl(PR_SET_DUMPABLE, 0)`; ошибка приводит к `INFRASTRUCTURE_ERROR`. Это закрывает проверку `/proc/1/fd/1` для процесса участника с тем же UID ([Linux `PR_SET_DUMPABLE`](https://man7.org/linux/man-pages/man2/pr_set_dumpable.2const.html), [Linux `/proc/<pid>/fd`](https://www.man7.org/linux/man-pages/man5/proc_pid_fd.5.html)).
- `_run_docker` заменён на одновременную передачу stdin и чтение stdout/stderr неблокирующим selector-циклом. Лимиты: протокольный stdout — 12 MiB, stderr Docker CLI — 64 KiB. При превышении потоков или таймауте CLI останавливается; прежняя неограниченная буферизация через `subprocess.run(..., stdout=PIPE, stderr=PIPE)` удалена. Cleanup также использует ограниченный reader и по-прежнему адресует только ID/name контейнера текущего runner-а.
- Добавлена fixture `protocol-write.cpp`: она делает только ограниченную попытку открыть `/proc/1/fd/1` и пишет `blocked` в обычный stdout только при `EACCES`/`EPERM`. Smoke ожидает `protocol-write: BLOCKED`; marker в JSON-канале приводит к провалу проверки парсинга.
- Обновлены policy/pipe unit tests, README и карточка агента. Чужие файлы, `context/STATE.md`, shared apps и другие feature-ветки не изменялись.
