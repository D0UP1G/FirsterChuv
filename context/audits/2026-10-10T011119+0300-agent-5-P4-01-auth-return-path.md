## Цель и исходное состояние

Поручение передало Agent 5 весь React frontend и разрешило независимо улучшать auth flow. В текущем `RequireRole` анонимный пользователь всегда попадал на `/login?next=/admin`; прямые переходы на `/matches/:id` и вложенные admin-маршруты теряли исходное место. Ссылка с формы входа на регистрацию также выбрасывала уже безопасный `next`.

Свежий `origin/develop` и merge-base feature подтверждены на `cc204e62`. В этой версии нет `context/agents/agent-5.md`, `frontend/design/README.md` или remote ref `feature/mvp-readiness-handoff`; согласно поручению карточку/новый план должен опубликовать координатор. Дублирующую карточку не создавал.

## Выполненные изменения

- `frontend/src/App.tsx`: `RequireRole` формирует `next` из текущих pathname, search и hash и передаёт его на login. Существующий `safeNext` на LoginPage по-прежнему ограничивает переход same-origin.
- `frontend/src/pages/LoginPage.tsx`: ссылка на регистрацию сохраняет проверенный `next`; `RegisterPage` уже переносит его дальше обратно на вход.
- `frontend/src/App.test.tsx`: регрессии проверяют сохранение match path/query/hash при переходе login → register и фактический возврат participant на match после входа.
- CodeMirror, безопасный Markdown/TeX, local draft namespaces и другие существующие UI не менялись.
- Изменены только `frontend/src/App.tsx`, `frontend/src/pages/LoginPage.tsx`, `frontend/src/App.test.tsx` и этот аудит. Backend, API contracts, конфигурация и `context/STATE.md` не менялись.

Связано с TEAM01, S02 и полным T02: участник должен попасть в защищённое рабочее место после входа, а роли и доступ остаются серверными. Реализован только маршрут возврата; права не расширялись.
