## Выполненные изменения

- Добавлен `TournamentParticipant` с UUID, FK на турнир и пользователя, unique `(tournament, user)`, status `ACTIVE/REMOVED`, numeric seed, added/removed timestamps.
- Добавлены БД ограничения: положительный seed или null; partial unique active seed на турнир.
- Добавлена initial participant migration `0002_tournamentparticipant` с dependency на `0001`.
- Реализован admin directory `GET /api/v1/admin/users`: только active participant, bounded `q`, limit/offset, только id/displayName, без email.
- Реализованы participant-scoped GET tournaments/detail/participants: active member видит только свои joined tournament; иной UUID возвращает 404. Participant roster DTO не раскрывает email.
- Реализованы admin-only POST/PATCH/DELETE participant actions. Assignment допускает только активную роль participant; повтор assignment идемпотентен, повтор DELETE не создаёт дубль; удаление переводит запись в `REMOVED`, повторная assignment использует ту же строку.
- Условное SQL increment/decrement active count совершается транзакционно с roster row changes; assignment ограничена participant cap. Смена seed не создаёт вторую assignment; duplicate active seed также закрывается DB constraint.
- Обновлены API/data-model/security/acceptance и README docs; общий `context/STATE.md` не менялся, поскольку feature не merged.

## Сверка с кейсом

Покрыта ручная часть `M03`: admin может найти зарегистрированных активных игроков, назначить участника, увидеть roster, задать/изменить/сбросить seed и логически снять участника до freeze. Admin account, inactive account, duplicate seed и переполнение cap отклоняются. Ручной seed — выбранный MVP вариант из кейса/роадмапа; ranking seed не реализован.

`T05` остаётся `NOT_RUN` целиком: нет реального match/bracket runtime, freeze service из A1-03.3, параллельного assignment/accept scenario, browser UI и интеграции. Проверка истории реального сыгравшего участника отложена до вызова freeze из bracket generation; сейчас roster API уважает `roster_frozen_at`, а история не hard-deleted.

## Решения и отклонения

- Реализуется numeric ручной seed, ranking seed оставлен будущим вариантом вне выбранного MVP.
- Неиспользуемые/removal history сохраняются мягким статусом; tournament hard delete доступен только для нефрозеного draft, где ещё не может быть сыгранного матча.
- API повторной assignment не меняет seed молча. Если существующему active entrant нужно изменить seed, используется отдельный PATCH.
- A1-03.2 уже включает основные SQL conditional cap guards; A1-03.3 дополнительно проверит race boundary, добавит freeze hook и отдельное evidence по транзакции bracket generation.
- Не редактировались ownership paths агента 2, `context/STATE.md` и чужие ветки.

## Блокеры и риски

Нет блокера для A1-03.2. Полного сценария T05 пока нет, поскольку bracket module отсутствует. SQLite short transaction/CAS pattern реализован, но многопоточный race не запускался; нельзя выдавать sequential API checks за доказательство concurrent acceptance. Freeze service ещё не создан.
