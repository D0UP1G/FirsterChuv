## Сверка задачи

ROADMAP v5 требует до PR #58/#59 исправить same-key admin read-before-write race и stale downstream winner после rematch. Принятое условие P2-05: downstream можно пересмотреть только до start; после старта исходный admin action отклоняется. Это часть P2-04 integration blocker, но не завершение всего P2-05/M08/T11/T20.

## Изменения

- `execute_match_admin_command` делает write reservation на match до первого read, затем проверяет actor, receipt и run. Exact same-key request сериализуется и возвращает прежний response; другой fingerprint остаётся 409. Whole-command SQLite busy retry ограничен тремя попытками, exhausted contention выдаёт 503 и откатывает effect.
- Rematch очищает только downstream slot, закреплённый за этим upstream match. Если downstream имел unstarted READY/WAITING run, run помечается SUPERSEDED, ready signals удаляются, current pointer/winner снимаются и матч возвращается в WAITING. Все действия находятся в одной транзакции.
- Если downstream уже начал работу, pure guard запрещает rematch; дополнительно persistence guard откатывает всё, если downstream snapshot неожиданно уже не является unstarted.
- Добавлен сценарный тест: оба полуфинала продвинули участников, финал настроен, один upstream rematch, старый winner/run сняты, новый winner продвигается в slot, финал заново конфигурируется; после старта финала следующий rematch отклоняется.
