## Решения и отклонения

Сохранена граница pure domain: здесь нет предположения, что любой callback имеет право менять результат. Вход — immutable typed receipt с идентификаторами run/участника/задачи, финальным verdict, server timestamp и active elapsed; admission/current-run/deadline/lease должны быть проверены и сохранены caller-ом. В первом срезе поддерживается явная политика `REMATCH`; набор штрафных verdicts и коэффициент штрафа конфигурируемы, CE нельзя добавить в штрафной набор. Default penalty `60_000 ms` — значение кода, не заявление, что команда выбрала его для реального матча; реальный запуск должен передавать опубликованный snapshot правил.

Порядок одинаковых elapsed разрешается server receivedAt и затем submission ID, поэтому порядок доставки receipt не меняет score. Одинаковый timestamp/elapsed с ID делает порядок стабильным. Никакие общие контракты или миграции этим срезом не изменены.

## Блокеры и риски

- Для persistence среза нужны актуальные Match/MatchRun lifecycle модели P2-01, clock/state P2-03 и согласованный typed accepted/result receipt с P3-04. PR #7/#11 были открыты и ещё не интегрированы на момент проверки.
- Unit receipt не доказывает, что server elapsed действительно соответствует приёму до deadline; ledger должен делать атомарный admission check и хранить исходные времена.
- Победитель пока не фиксируется транзакционно и не продвигается по сетке; delayed results из SUPERSEDED/неактуального run блокирует следующий слой, не данный алгоритм.
