## Выполненные изменения

- Добавлены `Invite` и `InviteAcceptance`, собственная миграция app tournaments, DB constraints на наличие expiry/use limit, положительный maxUses, usedCount ≤ maxUses и unique acceptance на пользователя.
- Добавлены strict create serializer и metadata serializer. `create_invite` генерирует URL-safe secret через `secrets.token_urlsafe(32)`, сохраняет только SHA-256, возвращает raw token единственный раз; create запрещён при freeze/неподходящем lifecycle.
- Реализованы admin-only, CSRF-protected create/list/revoke routes; список paginated и не содержит token/hash; revoke повторяемый и возвращает `204`.
- Реализован anonymous preview с `ScopedRateThrottle` `30/minute`, минимальным DTO, no-store и no-referrer headers; неизвестный token — `404`, истёкший/отозванный/исчерпанный — `410`.
- Реализован participant accept с auth/active-role/CSRF guards. Условное списание use, lifecycle check, существующий `assign_participant` (cap/freeze/status) и unique acceptance ledger находятся в одной транзакции. Повтор acceptance не расходует use; conflict состава откатывает use. Добавлен bounded SQLite lock retry через существующий service decorator.
- Настроен throttle scope `invite_preview`.
- Обновлены API, data model, parallel contract, security, acceptance и матрица требований. Зафиксировано, что результат пока только в feature и не закрывает full T04/S02.
- Обновлена карточка Agent 1; общий `context/STATE.md` не менялся, так как код ещё не интегрирован в `develop`.

## Решения и отклонения

Сохранён target contract v1. Чтобы retry одного participant был идемпотентным, acceptance ledger имеет unique `(invite,user)`. Условное обновление включает lifecycle predicate турнира: freeze не обходится даже для участника, у которого уже есть active roster entry. Повтор уже существующей acceptance остаётся no-op, включая последующий freeze/revoke, и возвращает контрактный `joined: true` без дополнительного расхода. Отдельный share-token access не реализовывался и остаётся P1-03.

## Блокеры и риски

- До merge это feature-only код; integrated STATE намеренно не обновлялся.
- Rate throttle cache остаётся process-local, как описано в security docs; текущий Compose запускает один API process. Proxy/IP topology и redaction access logs находятся в P1-03.
- P4-02 должен подключить invite browser/register flow; полный T04 до этого не закрыт.
