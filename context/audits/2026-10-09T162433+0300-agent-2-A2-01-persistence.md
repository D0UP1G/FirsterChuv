## Выполненные изменения

- Добавлены `CompetitionConfig`, ORM-модели `Match`, `MatchSlot`, `MatchRun` и миграция `competition.0001`, зависящая от `tournaments.0002`. Модели хранят ссылку на `TournamentParticipant`, два slot на match, исходящий target match/slot, BYE winner и последовательные runs.
- Добавлен транзакционный `generate_bracket`: замораживает roster и сохраняет сетку в одной транзакции; повторный вызов возвращает существующую сетку; ошибка после freeze откатывает его. Canonical roster упорядочивается через transient ranks, nullable seed не меняется в базе. BYE сохраняется как bracket state без создания `MatchRun`.
- Добавлены explicit `reset_bracket` и service `set_first_round_pairings`. Пары можно заменить только до старта; проверяется точное размещение каждого roster entry один раз, а весь план пересобирается, чтобы согласованно обновить bye winners и downstream slots. Некорректный pairing не очищает текущую сетку.
- Добавлены contract endpoints в собственной app: admin-only POST `/tournaments/{id}/bracket/generate` с CSRF, GET `/tournaments/{id}/bracket` для admin/активного участника. DTO применяет allowlist и не сериализует email/source.
- Добавлены persistence и API tests; доменный тест импортирует модуль абсолютным package path, чтобы он обнаруживался Django test runner.
- Обновлены только собственная карточка агента 2, `backend/apps/competition/` и этот аудит. `backend/config/settings.py`, `backend/apps/common/api_urls.py`, `context/STATE.md` и файлы агентов 1/3/4 не менялись.

## Решения и отклонения

- Для seed `null` временный rank создаётся только в памяти из порядка, возвращённого freeze service. Seed участника не назначается и не сохраняется генератором.
- Отдельные upstream FK и `next_match/next_slot` сохраняют происхождение будущего слота и направление продвижения. BYE match получает своего roster winner и BYE status, но не получает run.
- Pairings задаются целым первым раундом, чтобы проверять глобальную уникальность в одном изменении; генератор строит всю следующую часть сетки заново. HTTP-представление этого DTO ещё требует согласования.
- Для reset удаляются slot references до matches и предварительно очищаются `next_match/next_slot`, сохраняя их DB constraints. Reset не изменяет и не снимает roster freeze.
