## Выполненные изменения

- Создано приложение `backend/apps/submissions/` со своей моделью и миграцией для приватного source, idempotency/hash, неизменяемого времени приёма, queue state/lease, ограниченных diagnostics/metrics, атомарных счётчиков и durable result outbox.
- Admission принимает обязательные injected ports. В короткой SQLite transaction резервируются global/author/match capacity, запрашивается server-side permit, сохраняется source и accepted ledger, добавляется allowlisted событие. Idempotency повторяет прежний receipt, изменение тела под тем же ключом даёт conflict. Публичные metadata/event не содержат source и source hash.
- Реализованы author-only metadata/source/history методы и HTTP routes из API v1. POST требует session participant, CSRF и `Idempotency-Key`, строго проверяет body и при отсутствии production factory закрывается кодом `503 integration_unavailable`. Admin не может отправлять или читать чужой source. Private routes имеют no-store/no-referrer.
- Добавлены conditional FIFO claim, bounded lease/renewal, expiry recovery, пять попыток с backoff, stale-token guards, verdict allowlist, приватная CE-диагностика и outbox delivery через ResultSink. Infrastructure failure не создаёт verdict.
- Очередь ограничена 1000 глобально, 10 на автора и 20 на 1v1 match (2 участника MVP × 10); POST ограничен 30/мин на автора/матч. Лимиты применяются атомарно/через configured Django cache соответственно.
- AppConfig, URL include в `backend/apps/common/api_urls.py` и scope throttle зарегистрированы вместе с приложением согласно правилу регистрации A3 apps в `parallel-contracts.md`. Shared `common/contracts.py`, модели/сервисы A1/A2 и `context/STATE.md` не менялись.
- Добавлены Russian README и service/API tests; fake adapters размещены только внутри tests. Карточка agent 3 заранее отмечена `IN_PROGRESS` и содержит branch/base/paths.

## Решения и отклонения

HTTP routes добавлены сейчас, но без действующего CompetitionGateway/EventWriter/LanguageRegistry production factory возвращает service без adapters и POST завершает 503 до записи source. Это следует fail-closed контракту и не маскирует отсутствие P2-03/04 интеграции. Изменение URL include/settings ограничено явной app-registration процедурой из `parallel-contracts.md`. Лимит по match выведен из документированного формата MVP 1v1 и лимита каждого участника; throttle использует Django cache и не заменяет отдельную proxy/network-защиту P1-03.

## Блокеры и риски

- Нет production CompetitionGateway, accepted-ledger/event adapters и ResultSink из P2-03/04; поэтому HTTP 202 и реальная атомарная связка пока доступны лишь с тестовыми ports.
- Нет готового P3-03 JudgeProvider и готового ProblemCatalog для запуска worker; P3-04 реализует durable core/lease transitions, но не запускаемый worker и не sandbox execution.
- В многопроцессной конфигурации rate throttle требует общего Django cache. P1-03 proxy/network protections остаются отдельной задачей.
- P3-01 реальный Docker hostile/runtime proof и P3-02/P3-06 official package mapping не затрагивались этой feature-веткой.
