## Решения и отклонения

- Формальные schemas строгие и описывают именно synthetic fixtures, а не все runtime состояния или официальный пакет.
- PR #14 local ProblemCatalog shapes учтены структурными Protocol, без изменения чужой ветки. Подтверждение static type checker отсутствует: в проекте он не настроен.
- P1-02 не включает rulesets/branch protection и не объявляет required checks активными. Рекомендованы PR, merge commit и jobs `contracts-and-common-imports`, `backend`, `domain`, `sandbox-unit`.
- Обычный CI разделяет sandbox unit checks и ручной реальный Docker smoke. Workflow dispatch GitHub доступен только после размещения workflow в default branch `main`; P1-02 идёт только в `develop`, поэтому manual dispatch пока не активен. Sandbox harness не интегрирован в develop, локальные sandbox tests и реальный smoke — `NOT_RUN`.

## Блокеры и риски

- GitHub workflow ещё должен реально выполниться в PR; до этого его status — не PASS.
- Manual real-smoke workflow нельзя dispatch-ить, пока release не перенесёт его в default branch `main`; до этого реальный Docker smoke остаётся отдельным локальным/поздним проверочным шагом.
- Branch protection на `main` и `develop` выключена; владельцу нужно применить рекомендации отдельной настройкой.
- Отсутствие suites в текущем ref означает, что dynamic domain job здесь сделал no-op; PR #7/#11/#13 остаются чужими открытыми ветками.
- Это не закрывает P1-03 proxy/share access, P1-04 Compose, owner app CONNECT или полную security acceptance.
