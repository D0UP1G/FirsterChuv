## Цель и исходное состояние

Подключить страницу «Сетка и матчи» к реальным `GET/PATCH /matches/{id}`, start и админским действиям. В реальном стенде на `develop` `7819fc7`: матч с двумя игроками в сетке имеет статус `WAITING` до настройки, `GET /matches/{id}` отвечает `409 match_run_not_configured`. Страница исключала `WAITING` из первого раунда и не умела состояние «матч без запуска», поэтому организатор не мог открыть форму настройки.

## Выполненные изменения

- `frontend/src/pages/AdminMatchPage.tsx`: первый раунд выбирается по наличию двух игроков, а не по статусу; ответ `409 match_run_not_configured` открывает форму настройки по данным сетки (имена игроков, значения по умолчанию из турнира); карточка «Открыть матч» доступна для таких матчей. Панель действий организатора рендерится только при загруженном матче.
- `frontend/src/pages/AdminMatchPage.test.tsx`: +2 теста на реальном HTTP-контракте (настройка ненастроенного матча; `PATCH` с `Idempotency-Key`, CSRF и телом `{problemIds, matchDurationSec, startMode}` и последующим «Запустить матч»).

## Решения и отклонения

Матч без запуска не получает отдельного клиента для `GET`: данные игроков берутся из сетки, а форма отправляет обычный `PATCH`. Подключение кнопки «Готов» отложено: `POST /matches/{id}/ready` ещё нет (P2-03.4, A4).

## Блокеры и риски

- A3: READY-задачи в каталоге (P3-02.2); без них нельзя реально сохранить настройки и запустить матч.
- A4: `POST /matches/{id}/ready`; сообщение `match_runtime_conflict` приходит на английском («a configured problem is not ready for execution»), стоит заменить русским текстом на backend.
