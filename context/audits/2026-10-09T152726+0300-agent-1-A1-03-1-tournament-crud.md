## Сверка с кейсом

PDF, стр. 5, блок 1, требует создание соревнования с названием, описанием, датами, форматом и лимитом участников. Матрица связывает это с `M01` и `T03`. CRUD принимает эти данные, отклоняет неверный диапазон дат, cap меньше двух, неподдерживаемый формат/visibility, неизвестные/read-only поля; create/edit отклонены для participant. Есть тесты session CSRF, role, config/defaults, read/list/update/archive.

Полный `T03` остаётся `NOT_RUN`: slice находится в feature branch, нет browser acceptance и полной integrated проверки. `M03`/`T05` не покрываются A1-03.1 и остаются следующими задачами A1-03.2/.3. `shareTokenHash` и unlisted public-share access не реализованы; visibility здесь сохраняется как metadata. История сыгравших участников ещё не подключена, hard delete закрывается через draft-only + `roster_frozen_at` guard, а played-entry replacement будет отдельным контролируемым action.

## Решения и отклонения

- Реализован только формат `single_elimination`, как выбирает MVP contract; иные форматы кейса являются дополнительными.
- Запрос `startsAt`/`endsAt` обязан содержать обе даты; `endsAt` должен быть позже. Условия API camelCase проходят через общий parser.
- Выбран ограниченный диапазон match duration 60–7200 sec; сам кейс приводит 15–30 минут как обычный диапазон, не как жёсткое требование. Числовые guards отражены в API contract.
- Unlisted share token и публичные tournament reads отложены до соответствующего пути/интеграции; код не делает вид, что link-access уже работает.
- Не тронуты `backend/apps/competition/`, `backend/apps/events/`, `context/STATE.md` и чужие branches.
