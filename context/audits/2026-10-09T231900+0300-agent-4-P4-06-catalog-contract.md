## Цель и решение

Проверить UI consumer на точном server contract, который PR #32 интегрировал в `develop`, и не выдавать его за весь P4-03/P4-06. `CamelCaseJSONRenderer` уже превращает serializer `problem_id` в `problemId`, поэтому отдельный casing adapter не нужен. `api.readyProblems()` возвращал всю runtime page прямо UI. Теперь он сохраняет `count`, `next`, `previous`, а `results` проецирует только в selection fields `problemId`, `label`, `version`, `readiness`.
