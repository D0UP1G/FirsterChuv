# Пользовательские сценарии

У аккаунта глобальная роль. Создание новой учётной записи всегда даёт participant. Просмотр публичных турниров доступен без сессии. Admin account выдаётся management command/уполномоченным оператором, не формой регистрации.

## Администратор

1. Login → список турниров → «Создать». Название/описание/даты, одиночное выбывание, cap, public/unlisted, duration и опубликованное scoring rule.
2. Импортировать официальный пакет. Видеть ready/not-ready задачи и ошибки формата; связать нужный набор с матчами/раундом. Закрытые тесты в UI не показываются.
3. Назначить зарегистрированных participant либо создать invite с expiry/maxUses, скопировать ссылку. Можно отозвать ссылку и убрать ещё не игравшего участника.
4. Выставить seeds → сгенерировать bracket. На экране byes и будущие слоты. До старта исправить пары; валидатор не допускает дубликаты.
5. Выбрать manual или both_ready. При ручном старте начать матч; при auto участники подтверждают готовность.
6. Во время матча видеть score/status; при необходимости pause/resume/extend. Для technical result, replacement или rematch указать reason.
7. При timeout дождаться FINALIZING → result. Winner автоматически заполняет следующий слот; tie отображается как требующий переигровки, не случайной победы.
8. Открыть публичную ссылку/проектор. Завершить турнир после разрешения финала.

Для командного расширения импорт Яндекс доступен в admin UI отдельно. Нельзя назначить source-only imported problem, пока нет полного набора official тестов/чекера для собственного judge.

## Участник

1. Открыть invite. Аноним видит сведения о турнире и приглашение войти/зарегистрироваться, но не условия будущего матча.
2. Register/login → accept invite. Успешная активация добавляет в roster; repeat accept показывает уже выполненное присоединение. Expired/revoked/full даёт понятное сообщение.
3. Dashboard → свои турниры → ближайший матч. Видны соперник, длительность, правила; задачи закрыты до старта. Для both_ready нажать «Готов».
4. После старта открыть A/B/C/D. На странице условия, formula/images/examples/limits, editor, language/template, timer и task statuses.
5. Draft сохраняется в локальном хранилище и на сервере с ключом user/run/problem/language. При конфликте revision показывается восстановление, а не бесшумное затирание.
6. Submit → QUEUED/RUNNING → реальный verdict; OK/WA/TL/ML/RE/CE без reload. CE diagnostics и исходник видит только автор. Retry browser request использует тот же idempotency key.
7. Pause запрещает новые посылки и фиксирует часы. Timeout блокирует submit; FINALIZING объясняет, что проверяются уже принятые решения. Поздний ответ judge учитывает original received time.
8. Result → winner идёт в следующий матч; loser видит завершённый результат. Старый draft/code остаётся доступен владельцу.

Participant не может управлять турнирами, назначать других и отправлять в чужой match даже с известным UUID. Чужой source отсутствует в API, DOM и SSE.

## Зритель

1. Public URL → турнир, live bracket, текущие и завершённые матчи. Регистрация не нужна. Unlisted tournament требует share token.
2. Match → две дорожки, display names, score/leader, task grid A–D, attempts/latest verdict/time since last attempt, timer и короткая event feed.
3. После OK подтверждённо меняется task status и solvedCount; при смене leader — анимация обгона; после result — winner/advancement. Нет имитации движения по таймеру.
4. Reconnect → events after cursor либо новый snapshot без дублирования анимаций. Если connection потерян, виден stale/reconnect статус.
5. Projector → крупные элементы и контраст, без редактора/форм/админских кнопок. Можно открыть отдельно на большом экране.

Задачи разрешены в любом порядке. Прогресс по числу решённых сопровождается отдельными статусами каждой задачи: OK на D не должен выглядеть как доказательство решения A–C. «Застрял» означает наблюдаемую последнюю неуспешную попытку/время с неё, а не непроверенное утверждение о мыслях игрока.

## Demo

Один admin context, два новых participant contexts по invite, ещё два заранее назначенных participant и один anonymous spectator. Сетка на четыре игрока показывает полуфинал → финальный слот. Для отдельной проверки byes использовать три/пять участников. Сквозная демонстрация и hostile execution укладываются в заранее записанное видео до пяти минут.
